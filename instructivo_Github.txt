# 🏋️ GYM App - Guía Completa de Trabajo en Equipo

## 🤔 ¿POR QUÉ ESTE CAMBIO?
Problemas anteriores: Todos trabajábamos en la misma rama main, si alguien subía código roto afectaba a todos, no había control.
Solución: main protegido (código estable), develop para integración, ramas feature para trabajo individual.

## 🗂 ESTRUCTURA DE RAMAS
main ← CÓDIGO ESTABLE (protegido)
  ↑
develop ← INTEGRACIÓN 
  ↑
feature/login ← Compañero 1: Autenticación
feature/dashboard ← Compañero 2: Estadísticas

## 🚀 CÓMO TRABAJAR - COMANDOS

### ACTUALIZAR REPOSITORIO:
cd GYM
git checkout develop
git pull origin develop

### CREAR TU RAMA:
git checkout -b feature/login        # Compañero 1
git checkout -b feature/dashboard    # Compañero 2

### TRABAJAR Y SUBIR CAMBIOS:
git add .
git commit -m "feat: descripción"
git push origin feature/tu-rama

### CREAR PULL REQUEST:
1. Ir a: https://github.com/rjsoloaga/GYM
2. Click "Pull requests" → "New pull request"
3. base: develop ← compare: feature/tu-rama
4. Crear PR y esperar aprobación

## 🗂 ESTRUCTURA DE CARPETAS
lib/features/
├── socios/          # CRUD EXISTENTE (NO MODIFICAR)
├── auth/            # Para login/registro (Compañero 1)
└── dashboard/       # Para estadísticas (Compañero 2)

## 🛠 COMANDOS DOCKER
docker compose up
docker compose exec flutter-dev flutter pub get
docker compose exec flutter-dev flutter analyze

## 📋 FLUJO DIARIO COMPLETO

### AL EMPEZAR EL DÍA:
git checkout develop
git pull origin develop
git checkout feature/tu-rama

### DURANTE EL DÍA:
git add .
git commit -m "feat: avance en funcionalidad"
git push origin feature/tu-rama

### AL TERMINAR EL DÍA:
git checkout develop
git pull origin develop
git checkout feature/tu-rama
git merge develop 

## 🚨 REGLAS IMPORTANTES
- Trabajar SOLO en tu carpeta asignada
- Hacer PRs a DEVELOP (nunca a MAIN)
- Commit frecuentes con mensajes claros
- Probar que compila: flutter analyze
- Esperar aprobación antes de merge

## ❓ PREGUNTAS FRECUENTES
¿Por qué no push directo a main? → Para proteger código estable
¿Qué pasa si PR no aprobado? → Recibes comentarios para mejorar
¿Frecuencia de commits? → 1-2 por día con mensajes claros
